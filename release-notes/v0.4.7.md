# What's New in v0.4.7

v0.4.7 is a front-end-focused release: a unified visual design system across
both UI modes, a fully rebuilt settings experience, and fixes for several
interface bugs introduced alongside these improvements. No changes to query
generation, SQL safety enforcement, or the agent loop.

## ✨ New Features

**Live Conversation Settings** — Every setting in the conversation gear menu
now applies instantly to the discussion behind it. Toggle "Show technical
details" and exploration payloads appear/disappear in real time; change
"Visible Messages" and the thread reflows immediately — no closing, reopening,
or re-entering the discussion required.

**Defaults-Aware Minimalist Mode** — Minimalist mode now honors your saved
Discussion Defaults (and your default provider/data source) when starting a
new conversation via `/new` or the "+ New discussion" button. If defaults are
configured, you land ready to type with zero intermediate choices; if not,
you get clear guidance pointing at Settings → Defaults instead of a silent
misconfiguration.

**In-App Confirmation Dialogs** — All destructive actions (delete discussion,
clear messages, delete providers/connections, reset agent-loop settings) now
use styled in-app confirmation dialogs with keyboard support (Escape to
cancel, focus restored on close). The last native browser `confirm()` popups
are gone.

## 🔧 Improvements

- **United design language across both modes.** Full mode and Minimalist mode
  share one set of UI primitives (buttons, modals, dialogs, empty states,
  loading indicators), so visual fixes and improvements land in both at once.
  Accent-color theming now applies consistently everywhere — previously some
  controls kept hardcoded blue tints regardless of your chosen accent.
- **Accessibility pass:** visible keyboard focus indicators app-wide, Escape
  closes every dialog and popover, focus is restored to the trigger element on
  close, processing/streaming phases are announced via ARIA live regions, and
  secondary text now meets WCAG AA contrast in both themes.
- **Dark mode correctness:** code blocks, charts, and input surfaces no longer
  assume light theme at startup; chart colors initialize from the active theme
  immediately.
- **Cleaner iconography:** emoji glyphs (📌, ⚙️, payload toggles) replaced
  with consistent Lucide icons throughout the discussion list and tech-details
  panels; corrupted "up/down Request Payload" labels fixed.
- **Streaming performance:** removed a document-wide DOM observer that
  rescanned the page on every streamed character; table sorting, copy-SQL, and
  export wiring now use lightweight delegated listeners.
- **Settings architecture rebuilt internally** — each Settings tab is now an
  isolated component, making future settings work faster and less risky.
  (No settings were removed; everything is where it was.)

## 🐛 Fixed

- Sent messages could fail to appear as bubbles in conversations with existing
  history.
- The discussion list could become unresponsive after navigating between
  views and returning.
- Blank screen on launch under certain module-load failures.
- Changing a discussion setting appeared not to stick (changes saved but did
  not propagate to the open thread or subsequent dialog opens).
- Duplicate tag-chip styling conflicts; assorted dead styles and undefined
  CSS variables (`--font-3xs`, `--radius-lg`) referenced by tech-detail chips
  and rounded inputs.
- Focus ring missing on most custom buttons for keyboard users.
- Chart.js defaults assumed light theme until a theme-change event fired.
